# StashBay

> 在多个文件夹之间倒腾零散文件：放进暂存架，拖出去就完事，不用开两个资源管理器窗口对着拖。

Windows 上的文件中转站。**全部本地运行，不上传、不联网、不用注册账号。** 两个形态：一个用完即走的迷你搁架，一个能切分支、能写回、能撤销的完整工作台。

---

## 它能帮你做什么

### 极简中转（DropPoint 那种手感）
* **一键全部拖出**：拖住搁架顶部的 `[⤹ 共 X 项]` 徽章，一次手势把箱里所有文件批量丢进资源管理器，或微信、飞书、网页表单的附件框。
* **拖出即清空**：文件落到目标窗口后自动从箱里移除（默认开启，可关）。箱空了窗口淡出收回托盘，不用管它。
* **光标旁唤出**：按全局快捷键，搁架直接在鼠标所在的那块屏幕上展开，不用把鼠标滑回主屏。
* **晃动即存**：在资源管理器中选中文件并左右快晃鼠标，搁架就地出现，选中的文件自动入箱。
* **桌面悬浮小球**：贴边磁吸的小球，点击或轻拖即展开搁架，跨窗口倒腾文件更随手。
* **顶部只有四个按钮**：置顶、添加、展开、关闭。两个有后果的动作（原路写回、清空全部）在底部，带文字写着，不靠猜图标。

### 切分支时替你保管改动
* **自动认仓库**：箱子里的文件来自某个 Git 仓库时，写回目标自动取仓库根，分支一切就弹托盘通知，一键写回原位置。
* **不会写坏半截**：写入前先查目标文件有没有被别的程序占用（Excel、Word、IDE），有就提醒，不闷头写。
* **覆盖前先备份**：目标文件被覆盖前快照进本地内容寻址存储，写错了「撤销上次」一步还原。
* **内容一样就不写**：目标和暂存内容一致时跳过写入，保留原文件的修改时间，不去无谓触发构建或热更新。

### 一个完整工作台
* **多箱分组**：文件按项目、按客户、按用途分开放，箱名自定。
* **四种视图模式**：树状（展开查看条目层级）/ 列表（平铺紧凑行）/ 按来源目录（同一目录进来的聚成一节）/ 大图标平铺（大文件图标网格，双击打开或独立拖拽）。选中的模式持久保存。
* **三种写回模式**：原位置（按仓库相对路径）、其他根目录、指定路径；子路径可保留完整结构 / 只留文件名 / 全部拍平。
* **冲突策略**：询问 / 覆盖 / 跳过 / 自动改名，写之前先给你看一份预览。
* **历史与回滚**：每次写回都记明细，部分失败可以只重试失败的那几条。

### 界面说你的语言
18 门语言原生支持，界面词条每一门都译到位（18 张资源表键集完全一致，由测试强制）：简体中文、繁體中文、English、日本語、한국어、Deutsch、Français、Español、Italiano、Português (Brasil)、Русский、العربية（RTL 完整镜像）、हिन्दी、Bahasa Indonesia、ไทย、Türkçe、Tiếng Việt、বাংলা。深浅两套主题，语言和外观都能跟随系统。

## 支持范围

| 项目 | 支持情况 |
| :--- | :--- |
| **系统** | Windows 10 1809 及以上 / Windows 11（x64、ARM64） |
| **运行时** | .NET 10 桌面运行时（便携版自带，无需单独安装） |
| **暂存内容** | 任意文件、整个文件夹（含子目录结构） |
| **来源** | 资源管理器选中项、剪贴板文件、晃动时的资源管理器文件选中项 |
| **写回目标** | 本地磁盘、网络驱动器 / UNC 路径、Git 仓库 |
| **大文件** | 单个文件超过 2GB（长路径 > 260 字符同样支持） |
| **数据存放** | 全部在 `%LOCALAPPDATA%\StashBay\`；卸载只清程序与配置，这个文件夹留着，要彻底清空自己删 |
| **系统要求** | 需 .NET 10；安装版免管理员权限，装在 `%LOCALAPPDATA%\Programs\StashBay` |

## 快速开始

**装**：到 [Releases](https://github.com/rockbenben/048-stashbay/releases/latest) 下载 `StashBay-x.y.z-setup.exe` 双击装上（免管理员权限），或下 `StashBay-x.y.z-win-x64.zip` 解压即用。

**用**：装完按 <kbd>Win+Alt+S</kbd>，搁架出现在鼠标旁边。

此刻它是空的。去资源管理器里选中几个文件，再按一次 <kbd>Win+Alt+S</kbd> —— 文件已经在架子上。拖住 `[⤹ 共 3 项]` 徽章，拖到桌面上松手，三项都出去了，架子自动收回托盘。

第一次出结果 = 上面这四步。剩下的功能和设置，用上了再看不迟。

## 命令行参数（CLI）

`StashBay.exe` 支持以下命令行参数，可用于脚本自动化、第三方启动器或系统快捷集成：

| 参数 | 说明 |
| :--- | :--- |
| `--add <路径...>` | 将指定的一个或多个文件/文件夹加入暂存箱 |
| `--apply-here <目录>` | 将当前暂存箱中的文件写回到指定目录 |
| `--apply-original` | 按文件原位置（Git 仓库相对路径）直接原路写回 |
| `--group <组名>` | 配合 `--add` 使用，指定加入的暂存分组（不存在则自动创建） |
| `--minimized` | 最小化启动到托盘（开机自启模式） |
| `--show` | 唤出并显示主窗口 |
| `--quit` | 退出已在运行的 StashBay 实例 |
| `--unregister-shell` | 注销右键菜单、发送到快捷方式及开机自启项 |
| `--elevated-retry <操作ID>` | 提权以管理员身份重试历史中失败的写入操作 |

另有 `--smoke`、`--seed <workspace>`、`--shots <dir>`、`--probe <dir>`、`--inspect` 五个无头诊断参数供自动化测试与截图矩阵使用。

## 写回怎么用

搁架负责「中转」，工作台负责「落地」。要点只在**预览**那一步：按下「预览」先看一遍每个文件会写到哪、是新建还是覆盖、冲突怎么处理，确认无误再写。

* **原位置**：按文件在 Git 仓库里的相对路径写回原处——切分支前后托管改动就用这个。
* **其他根目录**：保持相对路径不变，整体搬到另一个根下。
* **指定路径**：三种子路径结构（完整相对路径 / 仅暂存项自身 / 全部拍平）配合四种冲突策略任选。

写完之后「撤销上次」可整批还原；部分失败时只重试失败的那几条，不用整批重来。所有写回记录留在「历史」里，按天数自动清理（默认 30 天，可设为永久）。

## 数据与存储路径

| 数据类型 | 本地存储路径 |
| :--- | :--- |
| **数据库** | `%LOCALAPPDATA%\StashBay\stashbay.db` |
| **覆盖前快照（Blob Store）** | `%LOCALAPPDATA%\StashBay\blobs\` |
| **用户配置** | `%APPDATA%\StashBay\settings.json` |
| **拖入内容缓存** | `%LOCALAPPDATA%\StashBay\clipboard\` |
| **拖出物化缓存** | `%LOCALAPPDATA%\StashBay\export\` |
| **运行日志** | `%LOCALAPPDATA%\StashBay\logs\` |

向前兼容旧版 `%LOCALAPPDATA%\FileStash\`：首次启动检测到旧目录就继续用它，不强制迁移、不丢数据。

## 已知限制

* **只用 Windows**。用的是 WPF 加 Windows Shell 集成（右键菜单、发送到、RestartManager 占用检测），没有跨平台计划。
* **暂存的是副本，不是链接**。文件放进箱子时内容已快照，之后改原文件不影响箱里那份；反之箱里这份改了也不会写回源文件。
* **一个实例**。多开会把参数转给最先启动的那个，不会开第二个窗口。
* **真拖放没法完全自动化**。批量拖出、粘到资源管理器这两条路径上的交互手感，验收脚本测得完行为、测不出手感（观感仍需人过一眼）。
